# log-analyzer

Автоматический анализатор журналов безопасности: выгружает события из PostgreSQL,
оценивает их на аномальность с помощью Isolation Forest, отправляет на анализ
GigaChat и присылает готовый отчёт письмом.

Проект посвящён защите рецепта крабсбургера от коварного Планктона 🍔
(учебный кейс: анализ журналов безопасности с двумя сценариями — реальная атака
и ложная тревога).

## Архитектура

    PostgreSQL (security_events)
            │  выгрузка последних N событий
            ▼
    Isolation Forest (только в v5)      ── численная разметка аномалий
            │
            ▼
    GigaChat (LLM-аналитик)             ── текст отчёта, вердикт
            │
            ▼
    events.json + report_*.txt + письмо (SMTP)

Две версии скрипта демонстрируют два подхода:

- **v4** — «чистый LLM»: модель получает сырой журнал и сама всё считает;
- **v5** — гибрид «ML-детектор + LLM-аналитик»: аномалии размечает Isolation
  Forest, сводку считает код, модель только интерпретирует готовые факты.

## Состав репозитория

| Файл | Назначение |
|---|---|
| `send_answer_v4.py` | базовый пайплайн: Postgres → GigaChat → письмо |
| `send_answer_v5.py` | гибрид: Postgres → Isolation Forest → GigaChat → письмо |
| `.env` | настройки (в гит не попадает — см. `.gitignore`) |
| `.env.example` | шаблон настроек |
| `events.json` | выгруженные события (создаётся при запуске) |
| `report_*.txt` | сохранённые отчёты (создаются при запуске) |

## Установка (Windows)

1. Установить Python с официального сайта, при установке отметить галочку
   **Add Python to PATH**.
2. Если команда `python --version` открывает Microsoft Store — отключить
   заглушку: Параметры → Приложения → Псевдонимы выполнения приложений →
   выключить `python.exe` и `python3.exe`. Работать можно и через `py`.
3. Создать и активировать виртуальное окружение:

       python -m venv myenv
       myenv\Scripts\Activate.ps1

4. Установить зависимости:

       pip install python-dotenv psycopg2-binary gigachat scikit-learn
   (для v4 достаточно первых трёх пакетов).

5. Установить PostgreSQL, задать пароль пользователю **латиницей**
   (кириллические пароли ломают подключение под Windows), создать базу и
   таблицу событий.
6. Рекомендуется в `postgresql.conf` установить `lc_messages = 'C'` и
   перезапустить службу — тогда ошибки подключения будут на английском и не
   будут маскироваться UnicodeDecodeError.

## Настройка .env

Пример:

    GIGACHAT_AUTH_KEY=...          # ключ авторизации GigaChat (API-ключ)
    PG_DSN=postgresql://user:pass@localhost:5432/log_analyzer
    PG_TABLE=security_events_attack1
    PG_LIMIT=200

    # необязательно, только для v5
    IF_CONTAMINATION=0.05          # ожидаемая доля аномалий (по умолчанию 0.05)
    IF_MIN_EVENTS=10               # минимальный размер выборки для обучения леса

    SMTP_HOST=smtp.yandex.ru
    SMTP_PORT=465
    SMTP_USER=robot@example.ru     # ящик, с которого уходит письмо
    SMTP_PASSWORD=app-password     # пароль приложения Яндекса, не пароль ящика!
    ALERT_TO=security@example.ru

Важно:

- файл должен быть сохранён в **UTF-8 без BOM**;
- в DSN для скриптов используется схема `postgresql://` — префикс
  `postgresql+psycopg2://` допустим, но скрипты автоматически приводят его
  к чистому виду;
- пароль — латиницей, без спецсимволов `@ : / %` (либо передавайте параметры
  подключения по отдельности);
- добавьте `.env` в `.gitignore` — секреты в гит не заливаются.

## Схема данных

Скрипты ожидают таблицу со следующими колонками:

| Колонка | Тип | Описание |
|---|---|---|
| `id` | serial | идентификатор события |
| `event_time` | timestamptz | время события |
| `event_type` | text | тип: login / process / network / file / service / share_access / account |
| `event_id` | text | код события |
| `level` | text | уровень: INFO / WARN / CRITICAL |
| `username` | text | учётная запись |
| `source` | text | IP-источник |
| `action` | text | действие |
| `result` | text | результат (success / failed и т. п.) |
| `computer` | text | компьютер |
| `created_at` | timestamptz | время записи |

## Запуск

    (myenv) C:\log-analyzer> python send_answer_v4.py   # базовый вариант
    (myenv) C:\log-analyzer> python send_answer_v5.py   # гибрид с Isolation Forest

Скрипт: подключается к Postgres → выгружает последние `PG_LIMIT` событий →
(v5: размечает аномалии) → сохраняет `events.json` → отправляет журнал в
GigaChat → сохраняет `report_*.txt` → отправляет отчёт письмом.

## Тестовые кейсы

| Таблица | Сценарий | Ожидаемый вердикт |
|---|---|---|
| `security_events_attack1` | атака Планктона: брутфорс → вход → создание пользователя → установка служб → вынос файлов → удаление логов | инцидент |
| `security_events_drunken_bob` | Боб дважды забыл пароль (внутренняя сеть, без CRITICAL) | ложная тревога |

Переключение кейса — переменной `PG_TABLE` в `.env`.

## Скрипты: v4 и v5 — в чём разница

### send_answer_v4.py — чистый LLM-подход

Модель получает сырой журнал и делает всё сама: считает сводку, ищет
подозрительное, пишет рекомендации. Сильные стороны — простота и хорошее
 описание kill chain по громким событиям. Слабые места (обнаружены на
реальных прогонах):

- **галлюцинации с числами**: в одном отчёте «проанализировано 49»,
  «всего 53», а сумма по типам — 54 (в журнале 50 событий);
- **перепутанные id** событий в «топе подозрительных»;
- **фантазии о времени**: «12:00–13:00... произошли ночью»;
- **ложная тревога на кейсе Боба**: две неуспешные попытки от известного
  сотрудника из внутренней сети модель трактует как атаку перебором и
  рекомендует блокировать IP — модель не умеет сказать «всё чисто»;
- **пропуски**: не замечены `mass_file_copy` (вынос рецепта!), остановка
  защитной службы и задача планировщика.

### send_answer_v5.py — гибрид «ML-детектор + LLM-аналитик»

Перед отправкой в GigaChat каждое событие размечается Isolation Forest'ом.
Признаки для леса (`build_features`):

- one-hot по `event_type` и `level`;
- час суток через sin/cos (цикличность: 23:00 и 01:00 «рядом») и флаг ночи
  22:00–06:00;
- внешний/внутренний источник (`10.*`, `192.168.*`, `172.16–31.*`, `127.*`);
- флаг неуспешного входа и нормированный счётчик неудачных входов пользователя;
- флаг «редкого действия» — идея «редкости бинарника»: пара
  (тип события, действие), редко встречающаяся в журнале, — индикатор
  постэксплуатации.

Параметры леса: `IsolationForest(n_estimators=200,
contamination=IF_CONTAMINATION, random_state=42)`. Каждое событие получает
`anomaly_score` (0..1) и метку `is_anomaly`. Если событий меньше
`IF_MIN_EVENTS`, лес не обучается — скоры нейтральны (кейс Боба из 4 строк).

Дополнительно: сводку по типам и уровням считает код (`Counter`), а не модель;
в промпт добавлены правила (см. ниже); шапка отчёта честно указывает
`GigaChat + Isolation Forest` и число аномалий.

### Сводная таблица различий

| Параметр | v4 | v5 |
|---|---|---|
| Поиск аномалий | сама LLM | Isolation Forest до LLM |
| Сводка по типам/уровням | считает модель (иногда ошибается) | считает код, передаётся готовой |
| Вердикт в конце отчёта | нет | обязателен: инцидент / подозрительно / ложная тревога |
| Контекст сети | нет | знает внутренние диапазоны |
| Зависимости | psycopg2, gigachat, dotenv | + scikit-learn |
| Новые переменные .env | — | `IF_CONTAMINATION`, `IF_MIN_EVENTS` |
| Типичные ошибки | галлюцинации чисел и id, ложная тревога на шуме | зависит от качества признаков |

### Правила промпта, добавленные в v5

1. Указывай только те id, количества и значения, которые есть в данных;
   не уверен — процитируй строку события.
2. Опирайся на `anomaly_score`: приоритет событиям с высокой оценкой.
3. Неудачные входы из внутренней сети от известного пользователя (1–2
   попытки, без CRITICAL) — вероятная ошибка пользователя, а не атака.
4. «Нерабочее время» определяй только по фактическому `event_time`.
5. Заверши отчёт вердиктом: инцидент / подозрительно / ложная тревога —
   с обоснованием.

### Зачем обе версии в репозитории

v4 — честная иллюстрация «чистого LLM-подхода» и его пределов; v5 — то же
место с ML-слоем. Запуск обоих скриптов на одном журнале — готовый
эксперимент: матрица 2×2 (кейс × версия) показывает, как меняется поведение
модели с численным детектором и без.

## Частые ошибки

- **UnicodeDecodeError при psycopg2.connect** — реальная ошибка подключения
  (неверное имя базы/пароль) замаскирована: libpq вернул локализованное
  сообщение в cp1251, а psycopg2 декодирует как UTF-8. Лечение: проверить
  DSN/пароль через `psql -U postgres -h localhost -d имя_базы`, установить
  `lc_messages = 'C'`.
- **«Пользователь не прошёл проверку подлинности»** — не тот пароль в `.env`
  или пароль изменился через `ALTER USER`, а файл не обновлён.
- **psql видит кракозябры** — пароль с кириллицей в cmd; используйте
  латиницу и подключение без строки DSN: `psql -U user -h localhost -d base`.
- **`python` открывает Microsoft Store** — заглушка; используйте `py` или
  отключите псевдонимы.
- **pip не находит пакеты / таймауты** — используйте зеркало:
  `pip install ... -i https://pypi.tuna.tsinghua.edu.cn/simple`.
- **`error: Microsoft Visual C++ 14.0 required`** — установите
  C++ Redistributable (или используйте `psycopg2-binary`, а не `psycopg2`).
- **Путь к проекту длиннее 260 символов** — перенесите проект ближе к корню,
  например `C:\Projects\log-analyzer`.

## Безопасность

- `.env` с ключами и паролями не попадает в гит (`.gitignore`).
- Пароль от почты — именно **пароль приложения**, а не основной пароль ящика.
- Ключ GigaChat хранится только в `.env`, не в коде.
