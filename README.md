# log-analyzer — отчёт по логам безопасности на почту

Простой конвейер: **PostgreSQL -> JSON -> GigaChat -> письмо на почту**.

Скрипт `send\\\\\\\_answer\\\\\\\_v4.py` берёт последние события из таблицы `security\\\\\\\_events`,
сохраняет их в `events.json`, отправляет GigaChat на анализ и присылает
отчёт аналитика безопасности письмом. Рядом остаются файлы:
`events.json` (входные данные) и `report\\\\\\\_ГГГГММДД\\\\\\\_ЧЧММСС.txt` (отчёт).

## 1\. Для работы проекта нужны:

Установленные:

* Python 3.10+ (проверено на 3.11)
* PostgreSQL, запущенный локально (порт 5432 по умолчанию)

Заполненный файл .env (Файл .env — скрытый текстовый файл (имя начинается с точки, поэтому на Linux он не виден при обычном просмотре). Используется для хранения ключей, паролей, токенов и другой чувствительной информации отдельно от кода программы. Файл читается библиотекой python-dotenv (load_dotenv()). Пароли и ключи в нем не зашифрованы, "безопасность" обеспечивается только тем, что файл не публикуется: его добавляют в .gitignore и держат локально.)

* Почтовый ящик Яндекс с **паролем приложения** (не обычный пароль от почты!)
Создаётся в Яндекс.Почте: Настройки → «Безопасность» → «Пароли приложений».

## 3\. Подготовить базу данных

Если написать просто `psql -U postgres`, на локальной машине соединение может упасть с
`FATAL: Peer authentication failed` — это нормально, подключайтесь по TCP:

```bash
psql -h localhost -U postgres
# если пароль спросят — введите пароль пользователя postgres
```

В консоли psql выполните:

```sql
CREATE DATABASE log\\\\\\\_analyzer;
\\\\\\\\c log\\\\\\\_analyzer

CREATE TABLE IF NOT EXISTS security\\\\\\\_events (
    id          BIGSERIAL PRIMARY KEY,
    event\\\\\\\_time  TIMESTAMPTZ NOT NULL,
    event\\\\\\\_type  TEXT,
    event\\\\\\\_id    INT,
    level       TEXT,
    username    TEXT,
    source      TEXT,
    action      TEXT,
    result      TEXT,
    computer    TEXT,
    created\\\\\\\_at  TIMESTAMPTZ DEFAULT now()
);
```

Добавьте пару тестовых записей, чтобы было что анализировать:

```sql
INSERT INTO security\\\\\\\_events (event\\\\\\\_time, event\\\\\\\_type, event\\\\\\\_id, level, username, source, action, result, computer)
VALUES
(NOW(), 'login', 101, 'INFO', 'alice', '192.168.1.10', 'attempt', 'success', 'pc-01'),
(NOW() - INTERVAL '1 hour', 'login', 102, 'WARN', 'bob', '10.0.0.5', 'attempt', 'failed', 'pc-02'),
(NOW() - INTERVAL '2 hours', 'login', 103, 'WARN', 'bob', '10.0.0.5', 'attempt', 'failed', 'pc-02');
```

Проверка: `SELECT \\\\\\\* FROM security\\\\\\\_events ORDER BY event\\\\\\\_time DESC LIMIT 10;`
Выход: `\\\\\\\\q`

## 4\. Заполнить `.env`

Создайте файл `.env` **в корне проекта** (рядом со скриптом). Скрипт читает
его через библиотеку `python-dotenv` при запуске и подставляет значения
в переменные окружения — в коде пароли не хранятся.

```env
# --- GigaChat ---
GIGACHAT\\\\\\\_AUTH\\\\\\\_KEY=ваш\\\\\\\_ключ\\\\\\\_авторизации\\\\\\\_в\\\\\\\_Base64

# --- PostgreSQL ---
PG\\\\\\\_DSN=postgresql+psycopg2://postgres:пароль@localhost:5432/log\\\\\\\_analyzer
PG\\\\\\\_TABLE=security\\\\\\\_events
PG\\\\\\\_LIMIT=200

# --- Почта (SMTP Яндекса) ---
SMTP\\\\\\\_HOST=smtp.yandex.ru
SMTP\\\\\\\_PORT=465
SMTP\\\\\\\_USER=mypochta@yandex.ru
SMTP\\\\\\\_PASSWORD=пароль\\\\\\\_приложения\\\\\\\_16\\\\\\\_символов
ALERT\\\\\\\_TO=получатель@yandex.ru
```

Пояснения к полям:

|Переменная|Что это|
|-|-|
|`GIGACHAT\\\\\\\_AUTH\\\\\\\_KEY`|ключ авторизации GigaChat API|
|`PG\\\\\\\_DSN`|строка подключения к Postgres; формат `postgresql+psycopg2://пользователь:пароль@хост:порт/имя\\\\\\\_базы`|
|`PG\\\\\\\_TABLE`|имя таблицы с событиями|
|`PG\\\\\\\_LIMIT`|сколько последних событий отправлять на анализ (200 обычно влезает в контекст модели; если строки «толстые» — снизьте до 50–100)|
|`SMTP\\\\\\\_USER` / `SMTP\\\\\\\_PASSWORD`|ящик-отправитель и **пароль приложения** Яндекса (не пароль от почты!)|
|`ALERT\\\\\\\_TO`|кому придёт отчёт|

⚠️ Не коммитьте `.env` в git! Добавьте его в `.gitignore`.

## 6\. Частые ошибки

|Ошибка|Причина и решение|
|-|-|
|`Peer authentication failed`|psql подключается через сокет. Используйте `psql -h localhost -U postgres`|
|`role "user1" does not exist`|Linux-пользователь ≠ роль в базе. Заходите под `postgres` или создайте роль: `CREATE ROLE user1 WITH LOGIN PASSWORD '...'`|
|`NotFoundError: 404 No such model`|модель указана неверно. В v4 модель не задаётся вручную — скрипт сам берёт её из списка доступных. Проверьте, что `.env` не содержит устаревшей `GIGACHAT\\\\\\\_MODEL`, и что скрипт запускается последней версии|
|SMTP `535` / ошибка авторизации|используете пароль от почты вместо пароля приложения. Создайте пароль приложения в Яндекс.Почте|
|`Таблица пуста`|в `security\\\\\\\_events` нет данных — добавьте тестовые записи (см. шаг 3)|

## 7\. Что лежит в репозитории

* `send\\\\\\\_answer\\\\\\\_v4.py` — основной рабочий модуль конвейера
* `events.json` — выгрузка событий из БД (создаётся при каждом запуске)
* `report\\\\\\\_\\\\\\\*.txt` — сохранённые отчёты (история анализов)
* `.env.example` — образец `.env` без секретов (переименуйте в `.env` и заполните)
